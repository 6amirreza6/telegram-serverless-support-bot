# ربات پشتیبانی تلگرام — کاملاً سرورلس

یک ربات کامل تیکت پشتیبانی که **تماماً روی زیرساخت خود تلگرام** اجرا می‌شود — بدون سرور، بدون هزینه هاست، بدون VPS. کاربران در چت خصوصی تیکت ثبت می‌کنند و تیم پشتیبانی شما از طریق یک پنل مدیریت کامل پاسخ می‌دهد. هیچ بخشی از این مخزن به شخص خاصی متصل نیست: شما دیپلوی می‌کنید، با یک کلید یک‌بارمصرف مالکیت را دریافت می‌کنید و در حدود پنج دقیقه رباتتان بالا می‌آید.

[English](README.md) | **فارسی**

## امکانات

- **گفتگوی دوسویه واقعی** — بعد از ثبت تیکت، *تمام* پیام‌های بعدی کاربر (متن، عکس، ویدیو، ویس، صوت، فایل، ویدیوگرد، استیکر، گیف، موقعیت، مخاطب، نظرسنجی) خودکار به تیکت فعال او متصل و به‌صورت زنده برای تیم پشتیبانی ارسال می‌شود.
- **پنل کامل پشتیبانی** — لیست تیکت‌های باز/در انتظار/بسته با شمارنده زنده، کارت تیکت با پیش‌نمایش آخرین پیام، تاریخچه صفحه‌بندی‌شده، پاسخ / بستن / بازگشایی.
- **تیکت خروجی** — شروع گفتگو با هر کاربر با آیدی عددی یا @یوزرنیم (تیکت مستقیماً در چت او ظاهر می‌شود).
- **جستجوی کاربر** — با آیدی عددی، بخشی از یوزرنیم یا بخشی از نام.
- **مدیر اصلی + ادمین‌ها** — مدیر اصلی می‌تواند از داخل پنل ادمین اضافه/حذف کند. فقط مدیر اصلی می‌تواند تیکت را **به‌طور کامل حذف** کند (همه پیام‌های ذخیره‌شده، با تأیید دو مرحله‌ای) و دسته‌بندی‌ها را مدیریت کند.
- **دسته‌بندی تیکت** (اختیاری) — لیست دوزبانه با کلید فعال/غیرفعال سراسری.
- **ضد سوءاستفاده** — بن کاربر با سکوت کامل، محدودیت پیام در دقیقه، فاصله بین دو تیکت، انقضای وضعیت‌ها و محافظت در برابر حدس زدن کلید مالکیت.
- **رابط دوزبانه** — فارسی و انگلیسی، انتخابی توسط هر کاربر؛ اعلان‌ها برای هر پشتیبانی **به زبان خودش** ارسال می‌شود. تاریخ‌های فارسی با تقویم جلالی نمایش داده می‌شود.
- **ارسال مقاوم** — تشخیص بلاک‌شدن ربات (403)، مدیریت «chat not found»، محدودیت نرخ (429) با یک تلاش مجدد هوشمند.
- **بدون زیرساخت** — کد و دیتابیس SQLite روی Telegram Serverless؛ دیپلوی اتمی (`push`) و تغییر اسکیما صریح (`migrate`).

## پیش‌نیازها

- [Node.js](https://nodejs.org/) نسخه 18 یا جدیدتر
- یک ربات ثبت‌شده در [@BotFather](https://t.me/BotFather) با قابلیت **Serverless فعال**: وارد ربات خود شوید → `Serverless` → روشن کنید.

## ⚡ نصب‌کننده وب (ساده‌ترین راه)

با ترمینال راحت نیستید؟ **[نصب‌کننده وب](https://6amirreza6.github.io/telegram-serverless-support-bot/)** همه‌چیز را در مرورگر شما انجام می‌دهد:

1. مراحل گرفتن توکن **CLI ACCESS** از BotFather را نشان می‌دهد و تنظیمات شما (آیدی مدیر، ادمین‌ها، دسته‌بندی‌های دوزبانه، زبان پیش‌فرض و محدودیت‌های ضدسوءاستفاده) را در همان صفحه جمع می‌کند — **هیچ داده‌ای به هیچ سروری ارسال نمی‌شود**.
2. از سورس همین مخزن یک پروژه کامل به‌همراه فایل تنظیمات شخصی `seed-config.js` می‌سازد و به‌صورت zip دانلود می‌کند.
3. در پایان فقط ۵ دستور CLI باقی می‌ماند: `npm install` ← `npx tgcloud login` ← `push` ← `migrate` ← `npx tgcloud run lib/seed`.

سورس این نصب‌کننده در پوشه [`docs/`](docs/) همین مخزن است — قبل از استفاده می‌توانید آن را بازبینی کنید.

## شروع سریع (CLI Access)

همه مراحل در ترمینال انجام می‌شود. توکن CLI ربات **هرگز از سیستم شما خارج نمی‌شود** — در پوشه `.tgcloud/` ذخیره می‌شود که در `.gitignore` هست.

```bash
# ۱) ساخت پروژه جدید (پوشه را می‌سازد و CLI را نصب می‌کند)
npm create @tgcloud/bot my-support-bot
cd my-support-bot

# ۲) افزودن کد این پروژه
#    محتویات این مخزن را داخل پوشه کپی کنید
#    (tgcloud/، package.json، tgcloud.jsonc — فایل‌های اولیه را جایگزین کنید).
#    با گیت:
git clone https://github.com/6amirreza6/telegram-serverless-support-bot tmp-clone
cp -R tmp-clone/tgcloud tmp-clone/tgcloud.jsonc tmp-clone/package.json .
rm -rf tmp-clone

# ۳) اتصال پروژه به ربات خودتان (توکن CLI Access را وارد کنید؛
#    BotFather → ربات شما → Serverless → CLI Access)
npx tgcloud login

# ۴) دیپلوی کد و سپس ساخت جدول‌های دیتابیس
npx tgcloud push
npx tgcloud migrate
```

### اولین اجرا: دریافت مالکیت (هیچ اطلاعات شخصی در کد نیست!)

**هیچ آیدی مدیری در کد هاردکد نشده است.** به‌جای آن، یک‌بار با یک کلید یک‌بارمصرف مالکیت را دریافت می‌کنید؛ کلید فقط در دیتابیس ربات و ترمینال شما وجود دارد:

```bash
npx tgcloud run lib/setup-key
```

CLI چیزی شبیه این چاپ می‌کند:

```
   /setup AB2C9DEF
```

این دستور را حداکثر تا ۳۰ دقیقه بعد، **از اکانت تلگرام خودتان** به ربات بفرستید. آن اکانت مدیر اصلی می‌شود، کلید نابود می‌شود و پنل مدیریت باز می‌شود. سپس از بخش `👥 ادمین‌ها` در پنل، تیم پشتیبانی را اضافه کنید — آن‌ها هرگز به CLI نیاز ندارند.

> کلید را گم کرده‌اید یا می‌خواهید ربات را به کسی دیگر بدهید؟ دوباره
> `npx tgcloud run lib/setup-key` را اجرا کنید — کلید جدید، قبلی را باطل می‌کند
> و مالکیت با موفقیتِ claim منتقل می‌شود.

**روش جایگزین: Seed در زمان استقرار.** اگر می‌خواهید آیدی مدیر، ادمین‌ها و دسته‌بندی‌ها بدون رفت‌وبرگشت تلگرامی ثبت شوند، فایل `tgcloud/lib/seed-config.example.js` را به `seed-config.js` کپی کنید (در gitignore است)، مقادیر خودتان را بگذارید و بعد از `migrate` دستور `npx tgcloud run lib/seed` را اجرا کنید. نصب‌کننده وب همین کار را خودکار انجام می‌دهد.

## دستورهای روزمره (CLI)

| دستور | کار |
|---|---|
| `npx tgcloud status` | تفاوت فایل‌های محلی با نسخه دیپلوی‌شده (آفلاین) |
| `npx tgcloud diff` | تغییرات خط‌به‌خط |
| `npx tgcloud push` | دیپلوی ماژول‌های تغییرکرده (اتمی، شامل حذف‌ها) |
| `npx tgcloud migrate` | بررسی و اعمال تغییرات `schema.js` |
| `npx tgcloud run lib/setup-key` | چاپ کلید تازه یک‌بارمصرف مالکیت |
| `npx tgcloud run lib/seed` | بارگذاری یک‌باره تنظیمات `seed-config.js` (مالک/ادمین/دسته‌ها) |
| `npx tgcloud pull` / `reset` | همگام‌سازی با کلاود / دورریختن تغییرات محلی |

در CI به‌جای `npx tgcloud login` متغیر محیطی `TGCLOUD_TOKEN` را ست کنید.

داخل تلگرام، پشتیبانی از `/panel`، `/search`، `/open`، `/stats`، `/cancel` استفاده می‌کند؛ کاربران `/start`، `/menu`، `/id`، `/lang` و `/cancel` را دارند.

## انتشار نسخه خودتان در گیت‌هاب

این مخزن برای عمومی‌بودن طراحی شده:

- **هیچ آیدی، توکن یا یوزرنیمی در کد نیست** — مدیر در زمان اجرا از دیتابیس خوانده می‌شود؛ درخت پروژه را grep کنید، چیزی شخصی پیدا نمی‌کنید.
- `.tgcloud/` (توکن CLI شما)، `tgcloud/lib/seed-config.js` (آیدی‌های شخصی شما) و `node_modules/` در gitignore هستند.
- داده کاربران هرگز وارد گیت نمی‌شود — در دیتابیس سرورلس ربات زندگی می‌کند.

```bash
git init
git add .
git commit -m "Telegram Serverless support bot"
git branch -M main
git remote add origin https://github.com/<you>/<repo>.git
git push -u origin main
```

قبل از پوش کردن نسخه شخصی‌سازی‌شده، با `git grep` مطمئن شوید آیدی یا توکنی اضافه نکرده‌اید.

## تنظیمات

همه اعداد در `tgcloud/lib/config.js` هستند:

| ثابت | پیش‌فرض | توضیح |
|---|---|---|
| `SETUP_KEY_TTL` | 1800 ثانیه | اعتبار کلید مالکیت |
| `SETUP_MAX_FAILS` | 5 | حداکثر تلاش اشتباه برای هر کلید |
| `MAX_TEXT_LEN` | 3900 | اندازه هر بخش پیام ذخیره‌شده (حد تلگرام 4096) |
| `MSGS_PER_MIN` | 12 | ضدترکیدگی: پیام تیکت در دقیقه برای هر کاربر |
| `NEW_TICKET_COOLDOWN` | 60 ثانیه | فاصله بین ثبت دو تیکت |
| `STATE_TTL` | 1800 ثانیه | انقضای وضعیت فلوهای چندمرحله‌ای |
| `HISTORY_PAGE` / `LIST_PAGE` | 5 / 6 | اندازه صفحه‌بندی |
| `SEARCH_RESULTS` | 8 | حداکثر نتایج جستجو |
| `TZ_OFFSET_MS` | 3:30+ | منطقه زمانی نمایش تاریخ (پیش‌فرض جلالی) |

## ساختار پروژه

```
tgcloud/
├─ schema.js              # users, admins, categories, tickets,
│                         #   ticket_messages, states, settings (بدون FK —
│                         #   یکپارچگی در کد تضمین می‌شود)
├─ lib/
│  ├─ config.js           # محدودیت‌ها، وضعیت‌ها، استخراج رسانه
│  ├─ store.js            # تمام کوئری‌ها؛ آیدی مدیر در جدول settings
│  ├─ i18n.js             # تمام متن‌های fa/en
│  ├─ ui.js               # کیبوردها، کارت‌ها، تاریخ جلالی
│  ├─ flow.js             # لایه ارسال: مدیریت 403/429، پیام همزمان
│  ├─ setup-key.js        # ماژول اجراشدنی از CLI → چاپ کلید /setup
│  ├─ seed.js             # اجرای یک‌باره seed-config.js (اختیاری)
│  └─ seed-config.example.js  # الگوی تنظیمات شخصی (کپی → seed-config.js)
└─ handlers/
   ├─ message.js          # مسیریاب: کاربر/پشتیبانی، ماشین وضعیت، فرمان‌ها
   ├─ callback_query.js   # تمام دکمه‌های شیشه‌ای (نام‌فضاهای u:* / a:*)
   └─ my_chat_member.js   # ردیابی بلاک/آنبلاک شدن ربات
```

قواعد پلتفرم که خوب است بدانید: هندلرها فایل‌های تخت هستند، `callback_data` حداکثر ۶۴ بایت است، `push` هرگز دیتابیس را تغییر نمی‌دهد و `migrate` هرگز کد را دیپلوی نمی‌کند، و هر ماژول در یک سندباکسی ایزوله روی سرورهای تلگرام اجرا می‌شود.

## مدل امنیتی

- **مالکیت** — یک‌بار از طریق `/setup <کلید>` دریافت می‌شود. کلید ۸ نویسه از الفبای ۳۲ نویسه‌ای (بدون حروف شبیه هم)، یک‌بارمصرف، با انقضای ۳۰ دقیقه و حداکثر ۵ تلاش اشتباه است و فقط سمت سرور ذخیره می‌شود. کلید تازه، قبلی را باطل می‌کند و claim موفق، مالکیت را منتقل می‌کند.
- **محل داده** — رکورد کاربران، تیکت‌ها و پیام‌ها در دیتابیس سرورلس *ربات خودتان* است. در مخزن هیچ‌کدام وجود ندارد.
- **حذف تیکت** — فقط مدیر اصلی، با تأیید دو مرحله‌ای و با پاک‌سازی همه ردیف‌های پیام.
- **بن** — کاربران بن‌شده کاملاً نادیده گرفته می‌شوند (بدون بازخورد برای اسپمرها)؛ پشتیبانی هرگز بن نمی‌شود.
